# qq-bridge-next

让 DeepSeek Harness 里的 AI 参与 QQ 群聊和私聊：既可以普通问答，也可以扮演一个会看消息、接话、潜水和记住群友的聊天伙伴。

本项目基于 [qq-bridge](https://github.com/Derpyu520/qq-bridge) 重构，通过 SnowLuma 的 OneBot v11 接口连接 QQ，由 [DeepSeek Harness（DSH）](https://github.com/deepseek-ai/deepseek-harness) 运行模型与工具。

```text
QQ ↔ SnowLuma（OneBot v11）↔ qq-bridge-next ↔ DSH ↔ 模型服务
```

> [!IMPORTANT]
> 本项目与 SnowLuma、DeepSeek、腾讯 / QQ 没有隶属、合作或背书关系，也不是上游 qq-bridge 的官方版本。它不向 QQ 或 SnowLuma 注入、挂钩，也不安装、打包或启停 SnowLuma。**仅限非商业用途。**

## 能做什么

### 普通聊天，也能选择性参与

每个群聊和私聊默认使用独立的 DSH 工作目录与会话上下文；不同会话分别排队，一个群的处理卡住不会阻塞其他群。

| 模式 | 使用场景 | 回复方式 |
| --- | --- | --- |
| `chat` · 普通聊天 | 问答、调试收发 | AI 回复自动发送到 QQ |
| `reserved` · 一代仿真 | 按规则控制参与频率 | 结合关键词、概率、活跃与冷场状态决定何时接话 |
| `reserved2` · 二代仿真 | 更自主的群聊伙伴，默认模式 | AI 用工具查看未读和最近消息，自行决定发言、等待或潜水 |
| `closed-agent` · 管理员代理 | 管理员在私聊中使用 DSH 本地能力 | **仅限管理员私聊**，可使用 DSH 完整本地工具 |

二代仿真支持 @、关键词、指定发言人等唤醒条件，以及等待新消息、沉睡前观察、主动话题、分条回复和发送频率限制。**没有回复不一定是故障，也可能是 AI 决定继续潜水。**

### 角色、人设与会话说明

- 通过角色卡调整人格和说话方式，仓库附带“小鲸鱼”和“傲娇助手”示例，角色文件位于 `roles/*.md`。
- 在控制台管理角色卡、聊天预设提示词，以及每个会话的开场说明。
- 为不同会话选择不同模式；会话模式覆盖即时生效，不必让所有群使用同一种互动方式。

### 图片、表情与语音

- 提取消息图片、读取合并转发内容；看图需要所选模型支持视觉。
- 对图片进行尺寸和体积归一化，支持 GIF 抽帧，减少送入模型的数据量。
- 同步、查找、发送和收藏表情，并为表情记录使用说明。
- 可选发送本地音频作为 QQ 语音，支持音量处理与发送限流；默认关闭，**不等于内置语音合成**。

图片归一化和音频处理会用到 FFmpeg；使用这些功能前请确保本机可用，或配置 `modes.reserved2.voice.ffmpegPath`。

### 记住话题、用词与群友

| 能力 | 用途 | 默认状态 |
| --- | --- | --- |
| 轻量记忆 | 记录当前话题、待说想法和成员印象 | 不依赖长期记忆压缩开关 |
| 词汇记忆 | 保存词语含义、用法和例句，支持会话内及全局词汇 | 开启 |
| 身份与称呼 | 按 QQ 区分群友、管理别名，避免只凭同名合并人物 | 开启，默认不在提示词中暴露 QQ 号 |
| 长期记忆 | 从消息归档压缩出事件、偏好、承诺和摘要，按话题检索 | 关闭 |
| 消息归档 | 将聊天原文保存在本机，供检索、压缩和来源删除使用 | 关闭 |

词汇可注入四种模式。成员印象按 QQ 保存，工具查询使用稳定的 `member-*` 标识；称呼学习按群隔离，自动别名候选需要不同消息中的明确 QQ 共现证据才能生效。

启用长期记忆需同时开启 `memory.enabled` 与 `memory.archive.enabled`。检索使用本机 SQLite 索引；记忆整理会额外调用模型，产生用量。仅关闭长期记忆压缩，不会关闭轻量记忆和词汇。

### 受限联网搜索

提供联网搜索和公网网页抓取，配置入口为 `webSearch`。搜索支持 DeepSeek 和 Bing；默认自动选择，实际行为取决于可用凭据及服务状态。网页抓取拦截内网和保留地址。

### 本地管理控制台

控制台默认位于 <http://127.0.0.1:3100>，包含八个页面：

| 页面 | 主要用途 |
| --- | --- |
| 运行总览 | 查看连接、运行状态和活动记录 |
| 会话与模式 | 管理会话、切换模式、设置开场说明 |
| 门禁 | 管理接入白名单、黑名单和成员策略 |
| 身份 | 查看与维护群友称呼、别名 |
| 记忆 | 管理轻量记忆、长期记忆与词汇 |
| 调度 | 调整唤醒、潜水、等待和发送节奏 |
| 工具与用量 | 查看工具配置、模型用量与费用估算 |
| 设置 | 配置模型、思考强度、角色与预设、连接及配置迁移 |

费用估算可用 `pricing.models` 覆盖价格，不代替模型服务商账单。

## 快速开始

### 1. 准备环境

- **系统**：macOS 或 Linux。
- **Node.js**：≥22.13；与 DSH 0.2.2 同机部署时需 ≥24.9。
- **DSH Web**：自行安装、配置模型服务并启动；已验证 `0.2.2-rc.1`。
- **SnowLuma**：按[上游文档](https://github.com/SnowLuma/SnowLuma)安装并登录，开启 OneBot WebSocket 服务端与 HTTP API。

DSH 和 SnowLuma 由你单独运行，桥接不会代为启动它们。

### 2. 安装并配置

在仓库目录执行：

```bash
npm ci
cp config.example.json config.json
```

不要使用 `--ignore-scripts`：安装后脚本会修补 `@snowluma/sdk` 与 `@snowluma/mcp` 的 ESM 导入。

编辑 `config.json`，先确认这些字段：

| 字段 | 说明 |
| --- | --- |
| `dsh.baseUrl` | DSH Web 地址，默认 `http://127.0.0.1:3080` |
| `dsh.provider` / `dsh.model` | DSH 中可用的模型服务与模型 |
| `snowluma.wsUrl` | OneBot WebSocket 地址，例如 `ws://127.0.0.1:3001` |
| `snowluma.httpUrl` | OneBot HTTP API 地址，例如 `http://127.0.0.1:3000` |
| `snowluma.accessToken` | OneBot 访问令牌，与 SnowLuma 设置一致 |
| `snowluma.homeDir` | 本机 SnowLuma 安装目录，供连接发现等功能使用 |
| `ownerQQ` | 管理员 QQ 号 |
| `allow.private` / `allow.groups` | 允许接入的私聊 QQ 号与群号 |

**默认白名单为空且不放行任何会话。** 先添加一个用于测试的私聊或群聊，不建议开启 `allowAllWhenEmpty`。

其余配置及默认值见 [`config.example.json`](config.example.json)。语音、消息归档和长期记忆默认关闭；模式引擎与新调度灰度开关也默认关闭，初次使用不必开启。

### 3. 安装后端预设与工具

#### 方案 A：使用 DSH 后端（默认，`backend.type: "dsh"`）

```bash
node scripts/setup-dsh.mjs
```

此命令会修改本机 DSH 配置，注册聊天预设、MCP 服务及插件。默认使用 `~/.dsh` 下的 `web` 配置；其他环境可通过 `DSH_HOME` 指定目录，并以命令参数指定配置名。

**安装完成后重启 DSH。** 安全聊天预设缺失时，桥接会拒绝创建相应会话，不会退回具备本地工具权限的默认预设。

#### 方案 B：使用 Antigravity CLI 后端（`backend.type: "agy"`）

先确认本机已安装并登录 `agy` CLI（运行 `agy --version` 可正常返回），然后执行：

```bash
node scripts/setup-agy.mjs
```

此命令会备份并更新 `~/.gemini/config/mcp_config.json`（注册三个安全 MCP 服务）以及 `~/.gemini/antigravity-cli/settings.json`（在 `permissions.allow` 中预放行这三个 MCP 服务）。然后在 `config.json` 中切换后端：

```json
"backend": {
  "type": "agy",
  "agy": {
    "command": "agy",
    "model": ""
  }
}
```

非 `closed-agent` 模式下，`agy` 后端会自动加载 `dsh/agent-presets/` 下的安全系统提示词、通过 `--disallowedTools` 禁用本地文件/命令工具，并注入 `QQ_BRIDGE_SELF_KEY` 隔离会话。

### 4. 启动并验证收发

```bash
./start.sh
```

打开 <http://127.0.0.1:3100>，使用 `state/console-token` 中的令牌登录；若配置了有效的 `consoleToken`，则使用配置值。

首次验证建议：

1. 在控制台检查 DSH 与 SnowLuma 连接。
2. 确认测试会话已加入白名单。
3. 将该会话切换为 `chat`，发送一条 QQ 消息验证收发。
4. 收发正常后，再切换到 `reserved2` 调整角色、唤醒和潜水行为。

## 日常使用

### 启停

```bash
./start.sh     # 前台守护运行，正常退出 5 秒重启，异常快速崩溃按 5~60 秒指数退避；Ctrl+C 停止
./restart.sh   # 重启本仓库实例，并在后台守护运行
./stop.sh      # 停止本仓库实例
npm start     # 单次运行，不自动重启
```

后台守护输出位于 `state/bridge-guard.log`。连接失败时，先检查上游进程、地址、令牌和白名单；二代仿真不发言时，还需检查唤醒条件、潜水状态与发送限流。

### QQ 管理命令

以下命令仅管理员可用，由桥接直接处理，不经过模型：

| 命令 | 作用 |
| --- | --- |
| `/status` | 查看当前会话、白名单、角色和运行状态 |
| `/role 小鲸鱼` | 切换角色卡；`/role off` 清除角色 |
| `/silent` / `/active` | 进入或退出静默状态；静默时仅管理员可对话 |
| `/reset` 或 `/new` | 重置当前会话，下次消息使用新上下文，并清理该会话记忆 |

角色及静默状态不是按会话独立选择的聊天模式；只想调整某一个群时，请使用控制台的会话模式设置。重置上下文不等于从模型服务或 DSH 中物理删除历史。

### 升级与旧配置

旧配置仍可读取，新键逐字段优先：

| 当前键 | 兼容旧键 |
| --- | --- |
| `modes.reserved` / `modes.reserved2` | `social` / `socialV2` |
| `memory.terms` / `memory.archive` | `slang` / `archive` |

启动不会自动改写配置；可在设置页预览并确认迁移，执行前备份到 `state/config-backups/`。控制台保存配置时统一写入新键。

旧词汇会在首次迁移时备份为 `.bak-terms-v2`，仅确认词条进入新词库；损坏或过新数据拒绝迁移并进入只读状态。身份历史迁移使用 `node scripts/migrate-identity.mjs` 预检，加 `--apply` 才写入，已有身份表时拒绝覆盖。升级前请备份 `config.json` 与 `state/`。

## 安全与数据管理

### 权限边界

- `chat`、`reserved`、`reserved2` 使用受限 QQ 与联网工具，不能执行本地命令或读写任意文件；发送目标须通过白名单及相关策略检查。
- `closed-agent` 仅限管理员私聊，拥有更高权限，请谨慎开启。
- 桥接管理服务仅在本机监听。请保护 `config.json`、`state/` 和控制台令牌，不要提交或公开它们，也不要将管理端口直接暴露到公网。
- `identity.exposeQqInPrompt` 默认关闭；仅未配置该键时兼容旧 `socialV2.privacy.exposeUserId`。这不是匿名化保证，聊天正文自身仍可能包含个人信息。

### 数据会去哪里

- 聊天内容经 DSH 发送给你配置的模型服务；使用记忆压缩时，待整理内容也会交给模型。
- 搜索关键词发送给所用搜索服务；网页抓取会访问模型提供的公网地址。
- 运行状态、日志、记忆及开启后的消息归档保存在本机 `state/`。消息归档默认保留期为 90 天，可配置。
- 本项目没有遥测。删除本机数据不会自动删除 QQ、DSH 或模型服务商保存的副本。

### 删除来源消息及派生记忆

先停止桥接，再执行：

```bash
./stop.sh
node scripts/archive-redact.mjs <group:群号或private:QQ号> <消息号> [更多消息号…]
```

此命令针对已启用消息归档的数据，清空目标消息的正文、昵称和媒体，并清理来源记忆、身份证据、检索索引、视图、会话消息副本及相关迁移备份；**不要只手动删除一行归档来代替来源清理。**

| 退出码 | 含义 |
| --- | --- |
| `0` | 删除完成，或已脱敏消息的重试清理成功 |
| `1` | 未找到消息归档目录（归档可能从未启用） |
| `2` | 检测到 `state/bridge.lock` 锁文件（请先停止桥接） |
| `3` | 未找到目标消息 |
| `4` | 归档已脱敏，但派生数据仅部分清理；查看错误并修复后，用同一消息号重试 |
| `64` | 命令行参数格式错误 |

> [!WARNING]
> 历史数据可能没有完整来源，无法保证精确到单条消息。无法可靠归因的相关旧轻量记忆、非人工词汇及受影响的全局学习称呼，会按隐私优先原则保守清理；人工词汇、无来源长期记忆与明确无关的条目保留。

<details>
<summary>来源判定、备份及日志的具体取舍</summary>

- 轻量记忆与词汇支持通过 `extra.sourceMessageIds` 提供来源，未提供时使用最近消息。编辑或合并后无法证明完整来源的条目不会伪装成精确归因；来源合并超出 50 个时标记为来源不完整，而不是截断。
- 全局及会话内词汇均核对来源消息号与 `evidence`。证据命中目标消息优先；证据全部可归因且明确无关时保留。`{}`、`[]`、旧原文或含未知项的混合数组不构成可靠归因，没有明确来源消息号可判断时仍保守清理。
- 迁移备份与当前记忆池使用同一判定规则。BOM、v0 头和旧非法作用域不会触发整份备份删除；无法解析或版本过新的备份则移除该份文件，并报告部分完成。删除失败会聚合错误，继续处理后续备份。
- 因目录或权限问题读取失败的文件只报告、不删除；修复前 CLI 重试仍返回 `4`。损坏或版本过新的当前记忆池、状态文件也保留原件，不阻断归档脱敏。
- `qq-activity.log` 及 `.1` 轮转文件中，有来源标记的日志仅删目标消息；无来源旧日志与 agent 输出保留时间、会话及脱敏占位，不保留正文。
- 来源删除和重置会作废当前及停放的记忆整理会话，阻止在途结果回写。移除本地 `memory-session.json` 引用不等于物理删除 DSH 服务端历史。
- 未解析称呼按会话清理；受影响的无来源全局 learned 称呼会撤销，但其他群的本地称呼保留。

</details>

`qq_memory_clear` 未指定类别时只清轻量记忆，保留长期记忆、词汇、称呼及压缩游标；这不是完整隐私删除命令。

## 开发与集成

```bash
npm run test:audit       # 完整离线回归，不连接真实 QQ / DSH
npm run privacy-scan     # 检查入库文件中的令牌、本机路径和真实 QQ 号
npm run preview:console  # 用离线夹具预览控制台
```

浏览器回归使用 `npm run test:console-ui`，需另行准备 Playwright 与 Chromium。其他探针及端到端脚本可能访问真实服务，运行前先查看其环境要求。

HTTP 接口使用 `/api/console/*`（管理）、`/api/agent/*`（工具回调）和 `/api/health`（状态）。均需控制台令牌；工具回调另需 `x-agent-call: 1` 及绑定当前会话的 `x-agent-token`，仅状态查询可不带会话令牌。管理接口拒绝智能体调用，旧 HTTP 地址返回 404。

修改 DSH 聊天预设时编辑 `dsh/agent-presets/` 下的源文件，再运行 `node scripts/build-agent-preset-patches.mjs`，不要直接修改生成的补丁。
